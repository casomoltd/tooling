# Working through the session list

A session list is the one file both of you write in. It is not a record, it is
not versioned, and it survives only as long as the work does. Everything here is
about keeping it usable by the person who did not do the work.

## What the file is for

**Actions only, and only the ones that need doing.** A durable fact belongs in
whatever owns it — the tracker item, the reference page, the code comment. If a
line is not something someone does, it is in the wrong file.

**No method here either.** How a thing is done belongs in a skill. A design for
something unbuilt belongs in a tracked item, with a one-line pointer here.

**It is not memory.** Facts get written here because the file is open, when each
already has a home and is better argued there. Writing to whatever file is open
is the failure this rule exists to stop.

## Link everything you name

**A line that names a document, a page, a message, an item or a folder and does
not link it has failed.** The reader should never have to search for something
you have just been reading. Name the thing, not its identifier, and link it.

**"Tracked" is not an answer.** If something is tracked, say where and link it.
A line saying an item is tracked, with no link, costs the reader exactly the
search the tracking was supposed to save.

**But a link is not a licence to restate the item, and here is the tell: a
tracker link belongs inside an action line, never in a list or table whose rows
are tracker links.** The moment the file grows a section of them it has become a
mirror of the tracker, and a reader will use the mirror because it is in front
of them. Two copies, and the stale one wins.

Such a section will describe itself as compliant — "pointers, not a second copy,
the detail lives on the item" — and that sentence is the warning sign, not the
defence. A row carrying a sentence of context *is* the second copy. Check the
section against this rule, never against its own description of itself: a
section that has to claim it is not duplicating usually is. If an item needs no
action from you now, it does not belong here at all.

**This governs the reply as much as the file.** A document named in a reply is a
document the reader wants to open, and saying it has been filed without the link
hands them a search instead of a file. It costs nothing at the point of writing,
because the tool that filed it has just returned the link, and it costs a
rummage at the point of reading.

## Carry the context when the link cannot

A link is the cheapest way to hand over context and it is not always enough.
**Where there is no document, or the document will not answer the question on
its own, put enough in the line that the reader can act without going and
finding out.** Three cases where this bites:

- **A question you are asking them.** Give the reasoning, the options and your
  recommendation. "Decide the basis" is not a question anyone can answer; the
  candidate values, where each comes from, and what turns on the choice, is.
- **A reference the reader will not recognise.** A code, a row number, a clause,
  an internal name. Say what it is the first time.
- **A finding that lives inside a large document.** Quote the sentence. A link
  to a long document is not a citation of one line in it.

The test: **could they act on this line without asking you a question?**

## Answer the question that was asked

Annotations in this file are questions, and they are the highest-priority work
in it. **A question asked twice is a failure the second time.** If the answer is
"no", say no and say why; if it is "it depends", give the conditions. Do not
answer an adjacent easier question and move on, and do not park it back into the
file in the same words.

Where a question has two halves, answer both.

## Say what changed and what it cost

When reporting back, in this order:

1. **What is done**, with links.
2. **What you got wrong**, plainly, once, with the correction. Do not tally, do
   not apologise, do not narrate the discovery.
3. **What is still open**, and who holds it.
4. **What you did not do**, and why. Scope you dropped silently is scope the
   reader thinks is finished.

**Findings you did not act on need a reason.** Silence is not one.

## Do not repeat yourself

**A figure, a date or a conclusion lives in one place, and everywhere else
points at it.** Two copies drift, and the wrong one is quoted by whoever finds
it first. This applies inside the file and between the file and the tracker.

**Do not write a number into a durable page before it is settled.** Link the
working and say TBD. A figure on a page is read as established however it was
meant, and removing it later costs more than never writing it.

## Read the page that owns it before you put it on the list

**An open question found while searching is not open until the page that owns it
says so.** Check there first. An archive is worked over repeatedly, and the
thing that looks like a discovery is usually a question somebody already
answered and did not think to mention again.

**The cost is worse than wasted effort.** A question on the list is a claim that
nobody knows the answer, and the next reader believes it — including a claim
that a document does not exist when it is already filed.

## What somebody else holds is not tracked here

**A thread waiting on a reply is tracked where the reply will arrive, not here.**
The list is what somebody has to *do*. A chase that has gone out and is waiting
is not a thing to do; it is a thing to notice when it does not come back.

Carrying it in both places is the duplication this skill exists to stop: the
inbox is current by definition and the list goes stale the moment a reply lands,
so the two disagree and neither says which is right.

**The exception is when the wait itself needs an action** — a deadline that
expires, a chase that has to go if nothing arrives by a date. Then the action is
what goes on the list, with the date.

## Close threads

The section that grows is the one nobody is closing. When an item is done,
delete it; when it is superseded, delete it and state the current position; when
it turns out to belong somewhere else, move it there and delete it here.

**An item that has been on the list through three rewrites is telling you
something** — usually that it is not an action, or that it is blocked on
something nobody has named. Say which.
